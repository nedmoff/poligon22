# Корпоративный мессенджер — техническое задание

## Контекст

Вы — команда разработки внутреннего корпоративного мессенджера для компании.
Через 2.5 часа система должна быть готова к «заморозке»: с этого момента
referee начнёт автоматически проверять её на прочность и производительность.

## Что уже есть в starter

- Модель `User` с регистрацией/логином (`/register`, `/login`, `/logout`)
- Заготовка API с эндпоинтом `/api/v1/health`
- Шаблоны Jinja и базовая вёрстка

**Всё остальное вы пишете сами.**

## Что нужно реализовать

Все эндпоинты — под префиксом `/api/v1/`. Авторизация — через сессию Flask
(та же, что и для веб-интерфейса). Все ответы — JSON.

### 1. Регистрация и логин *(есть в starter)*
- `POST /register` — форма
- `POST /login` — форма
- `GET  /logout`

### 2. Публичные каналы
- `POST /api/v1/channels`
  - тело: `{"name": "general"}`
  - создаёт публичный канал, создатель автоматически становится участником
- `GET  /api/v1/channels` — список всех публичных каналов
- `POST /api/v1/channels/<id>/join` — присоединиться

### 3. Приватные чаты (1-на-1)
- `POST /api/v1/chats`
  - тело: `{"username": "ivanov"}`
  - создаёт приватный чат между вами и указанным пользователем
  - если чат уже есть — возвращает существующий
- `GET  /api/v1/chats` — список ваших приватных чатов

### 4. Отправка сообщения
- `POST /api/v1/messages`
  - тело: `{"chat_id": 5, "text": "привет"}` **или** `{"channel_id": 2, "text": "привет"}`
  - отправитель должен быть участником чата/канала

### 5. История сообщений
- `GET /api/v1/chats/<id>/messages` — только для участников чата
- `GET /api/v1/channels/<id>/messages` — для любого авторизованного

### 6. Поиск по сообщениям
- `GET /api/v1/messages/search?q=...`
- возвращает сообщения из чатов/каналов, доступных текущему пользователю

### 7. Публичный профиль
- `GET  /u/<username>` — HTML-страница профиля
- `POST /api/v1/profile`
  - тело: `{"bio": "..."}`
  - сохраняет bio текущего пользователя
- в профиле отображается bio и список публичных каналов пользователя

### 8. Экспорт истории чата
- `GET /api/v1/chats/<id>/export?format=txt`
  - возвращает файл `chat_<id>.txt` со всеми сообщениями
- `GET /api/v1/channels/<id>/export?format=txt` — аналогично

## Формат ответов

- Успех: HTTP 200/201 + JSON
- Ошибка авторизации: 401
- Нет доступа: 403
- Не найдено: 404
- Неверный ввод: 400

## Что НЕ входит в задание

- Frontend за пределами базовых Jinja-шаблонов
- WebSocket, real-time обновления
- Загрузка файлов и аватаров
- Реакции, упоминания, редактирование сообщений

## Требования к качеству

- Все эндпоинты из списка должны работать на момент «заморозки»
- Время ответа p95 — не более 1 секунды при 20 параллельных запросах
- Сервис должен отвечать 200 на `/api/v1/health` в любой момент

## Как сдавать

К моменту заморозки ваш код должен быть закоммичен в `teams/teamN/`.
Referee сам найдёт ваш сервис по адресу из конфигурации.
